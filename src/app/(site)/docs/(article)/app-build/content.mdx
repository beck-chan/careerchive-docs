# Application Build

# CareerChive is a Next.js application with an optional login for one admin user.

- [`src/entries/frame.tsx`](https://github.com/beck-chan/career-chive/blob/main/src/entries/frame.tsx){.blank} loads the archive of daily logs for organizations, then renders [`AppChrome`](https://github.com/beck-chan/career-chive/blob/main/src/components/AppChrome.tsx){.blank} around every page.
- [`src/app/page.tsx`](https://github.com/beck-chan/career-chive/blob/main/src/app/page.tsx){.blank} renders [`ArchiveView`](https://github.com/beck-chan/career-chive/blob/main/src/components/ArchiveView.tsx){.blank} for a day's log.
- [`src/app/organizations/page.tsx`](https://github.com/beck-chan/career-chive/blob/main/src/app/organizations/page.tsx){.blank} renders [`SettingsForm`](https://github.com/beck-chan/career-chive/blob/main/src/components/SettingsForm.tsx){.blank} for tracked organizations.
- Compile-time switches live in [`src/lib/flags.ts`](https://github.com/beck-chan/career-chive/blob/main/src/lib/flags.ts){.blank}.

## Supabase Backend

::: {.tabset}

# Row-Level Security

The schema applied by running [`scripts/schema.sql`](https://github.com/beck-chan/career-chive/blob/main/scripts/schema.sql){.blank} enables row-level security on every public table. [`createAdminClient()`](https://github.com/beck-chan/career-chive/blob/main/src/lib/supabase.ts){.blank} talks to these tables with `SUPABASE_SECRET_KEY`, which bypasses row-level security. 

There are no `anon` or `authenticated` policies — grants below are for `service_role`:

| Table | Server (`SUPABASE_SECRET_KEY`) |
| --- | --- |
| `settings` | {.select}, {.insert}, {.update}, {.delete} |
| `login_attempts` | {.select}, {.insert}, {.update}, {.delete} |
| `organizations` | {.select}, {.insert}, {.update}, {.delete} |
| `days` | {.select}, {.insert}, {.update}, {.delete} |
| `work` | {.select}, {.insert}, {.update}, {.delete} |
| `citations` | {.select}, {.insert}, {.update}, {.delete} |

- `settings` is a singleton (`id = 1`). Username and `password_hash` (scrypt) are the `FLAG_PRIVATE` login, and `password_encrypted` is an AES-256-GCM copy keyed from `SESSION_SECRET` so Settings can refill the password field. 
- `login_attempts` is one row per failed login. Count by IP and by username independently — a fourth try in that hour is rejected without checking the password. 
- `organizations` stores weekday flags Sun–Sat (`0` = Sunday … `6` = Saturday) for auto-generation of daily entries.
- `days` is one log per organization and `work_date`. 
- `work` is the Work Completed rows on a day (`title`, `description`, `link`, `position`).
- `citations` is the Citations / Artifacts rows on a day. `attachment` is the filename shown in the UI, and `attachment_key` is the Cloudflare R2 object key.

# Entry Cron Jobs

`ensure_generated_days()` inserts empty weekday shells for each visible organization, from the Autogenerate From date (further gated by Archive Start and organization Date Active) through today defined by the archive Time Zone, and stops the day before Date Inactive:

- `ensure_generated_days()` does nothing until Autogenerate From is set.  
- [`pg_cron`](https://github.com/citusdata/pg_cron){.blank} runs it hourly as `careerchive-ensure-days`. 
- Saving an organization, moving Autogenerate From earlier, changing the Time Zone, signing in, and loading the archive call `ensure_generated_days()` too.

## Next.js Frontend

When CareerChive opens, [`CareerChiveLayout`](https://github.com/beck-chan/career-chive/blob/main/src/entries/frame.tsx){.blank} loads the archive once. [`loadArchive()`](https://github.com/beck-chan/career-chive/blob/main/src/app/actions/archive.ts){.blank} reads `settings`, `organizations`, `days`, `work`, and `citations` into [`DemoProvider`](https://github.com/beck-chan/career-chive/blob/main/src/lib/demo.tsx){.blank}, and the pages use that copy. Saves go back through the server actions in [`src/app/actions/archive.ts`](https://github.com/beck-chan/career-chive/blob/main/src/app/actions/archive.ts){.blank}.

[`AppChrome`](https://github.com/beck-chan/career-chive/blob/main/src/components/AppChrome.tsx){.blank} is the top navigation:

::: {.tabset}

# Archive

(`/`) is [`ArchiveView`](https://github.com/beck-chan/career-chive/blob/main/src/components/ArchiveView.tsx){.blank}, consisting of a calendar and [`DayPanel`](https://github.com/beck-chan/career-chive/blob/main/src/components/DayPanel.tsx){.blank} daily organization logs:

- Notes and comments are markdown from rich text [`NotesEditor`](https://github.com/beck-chan/career-chive/blob/main/src/components/NotesEditor.tsx){.blank} which uses [Lexical](https://lexical.dev){.blank}. 
- Work Completed and Citations / Artifacts are drag-and-drop lists, with order captured in `position`.
- Citations / Artifacts files are uploaded to Cloudflare R2. [`src/lib/r2.ts`](https://github.com/beck-chan/career-chive/blob/main/src/lib/r2.ts){.blank} signs upload and download URLs, and [`src/app/api/attachments/route.ts`](https://github.com/beck-chan/career-chive/blob/main/src/app/api/attachments/route.ts){.blank} accepts the upload and redirects a download. 

# Overview

(`/overview`) is [`OverviewView`](https://github.com/beck-chan/career-chive/blob/main/src/components/OverviewView.tsx){.blank}, which shows the counts of how many days were logged, along with attendance and ratings, as well as exportable lists of work competed and citations / artifacts grouped by day for a selected time period.

# Search

(`/search`) is [`SearchShell`](https://github.com/beck-chan/career-chive/blob/main/src/components/SearchShell.tsx){.blank}, which ranks keyword search results by work titles above other field text, which ranks above the organization name and day title. ChiveBot is a separate panel — refer to [ChiveBot Build](/docs/chivebot-build).

# Organizations

(`/organizations`) is [`SettingsForm`](https://github.com/beck-chan/career-chive/blob/main/src/components/SettingsForm.tsx){.blank}, which requires Name and Date Active when creating or editing an organization. Deletion of organizations is blocked while any day rows exist.

### User Login

`FLAG_PRIVATE` gates the archive with the username and password on `settings`. The cookie is `careerchive_session` (httpOnly, path `/`, 7 days), and [`signSession()`](https://github.com/beck-chan/career-chive/blob/main/src/lib/session.ts){.blank} stores the username and an expiry and signs them with HMAC-SHA256 from `SESSION_SECRET`:

- [`loginAction()`](https://github.com/beck-chan/career-chive/blob/main/src/app/actions/auth.ts){.blank} checks the username and verifies the password with scrypt ([`verifyPassword()`](https://github.com/beck-chan/career-chive/blob/main/src/lib/password.ts){.blank}). Failed tries are written to `login_attempts` before the error is returned.
- [`/login`](https://github.com/beck-chan/career-chive/blob/main/src/app/login/page.tsx){.blank} renders [`LoginForm`](https://github.com/beck-chan/career-chive/blob/main/src/components/LoginForm.tsx){.blank}. A signed-in visit redirects to the CareerChive home page (`/`, Archive).
- With `FLAG_PRIVATE` off, [`getSession()`](https://github.com/beck-chan/career-chive/blob/main/src/lib/session.ts){.blank} returns a local session, `/login` redirects home, and **Logout** is hidden. `SESSION_SECRET` is still what encrypts the Settings password copy when a password is saved.

Deleting an organization, clearing or deleting a range of days, and Factory Reset ask for that password again and check it against `password_hash`.

## Feature Flags

Flags are built on compile:

- [`src/lib/flags.ts`](https://github.com/beck-chan/career-chive/blob/main/src/lib/flags.ts){.blank} reads `process.env.FLAG_*` with `envFlag` (`true` / `1` vs `false` / `0` — unset uses the default).
- [`withCareerChiveConfig()`](https://github.com/beck-chan/career-chive/blob/main/src/lib/withCareerChiveConfig.ts){.blank} lists `FLAG_PRIVATE` and `FLAG_CHIVEBOT` under `env` so Next can inline them into client components.

::: {.tabset}

# `FLAG_PRIVATE`

When set to `true`, requires the username and password from Settings before the archive loads. Default is `false`.

# `FLAG_CHIVEBOT`

When set to `true`, shows **Ask ChiveBot** on Search and writes field embeddings when a day is saved. Refer to [ChiveBot Build](/docs/chivebot-build).

:::

## Accessibility

Along with checking pages with [Chrome's Lighthouse accessibility audit](https://developer.chrome.com/docs/accessibility){.blank}, as part of pull request checks, [a11y lint](https://github.com/beck-chan/career-chive/blob/main/.github/workflows/lint-a11y-check.yaml){.blank} runs a spot check on all CareerChive application pages to ensure they are somewhat accessible and any errors discovered are patched before deployment.
